日期：2026-10-20，Asia/Shanghai。状态：待用户确认。本文件的 v3 是第三版规划，不代表软件已升级；上一轮 v2 也是提案，尚未实施。实现基线：`39525e6b3333915d229323e1ae5511d4ce406236`。

本轮完成公开 Skills 研究与方案留档。后续实施、付费或免费生图、试样及整套重做均待确认；本轮不修改生产 Skill 和脚本。研究涉及 6 个仓库中的 15 份 SKILL.md，以及配套规范和服务商资料。来源、固定提交和内容校验记录见 [研究记录](../research/2026-10-20-skills-v3-research.md) 与 [来源清单](../research/2026-10-20-skills-v3-sources.json)。这里只借鉴经过筛选的方法，没有安装或运行第三方 Skills。

目标仍是：输入准确推广关键词和小说／推文正文，agent 完成改编、分镜、生图、排字、验收，交付按顺序上传的漫画图集 ZIP。用户选定的模型、风格、页数和费用约束优先。更换模型时，由 agent 查阅实际服务商的当前资料，再确定画面生产方式与请求调度方式。

**1．这次需要改变的关键决策**

v2 主要补救气泡、裁切与人物表演，但仍偏向把所有模型放进同一种“每格独立生成”的流程。v3 同时处理漫画创作和模型适配：先定义读者要看到什么，再选择模型能稳定完成的生产路线，并用实际画面验收。

| 决策 | 现有实现／上一版方案 | v3 拟采用 |
|---|---|---|
| 生成单位 | 默认所有正文独立两格插画 | 按能力与试样选择整页、整页无字画稿或独立分格；每种路线保持同一美术目标 |
| 文字 | 固定下方白框；v2 拟加气泡 | 脚本先确定文字功能、说话者、阅读顺序与安全区，再安排画面和排字 |
| 叙事 | 固定16张易变成梗概 | 先确定推广覆盖区间与关键因果，页数随剧情和阅读密度决定；明确页数则在约束内规划 |
| 一致性 | 每次重复外观描述 | 角色、服装、地点、道具分别编号并记录状态；实际参考输入和文字描述分开记载 |
| 质量 | 文件、文字框检查为主 | 视觉、剧情、文字、技术分开验收；技术通过不能抵消画面不合格 |
| 调度 | Agnes 案例串行约60秒 | agent 查资料并生成有依据的模型配置；串并行、频控、轮询分别决定 |
| 返工 | 改计划后复跑 | 稳定页面／分格 ID，记录依赖，仅失效受影响的内容与最终导出 |

**2．先把正文改成漫画脚本，保留原文的因果**

区分两种任务：用户提供推广推文时，优先改编已选正文；提供完整小说时，默认制作推广节选，确定钩子、覆盖范围、不能提前揭示的信息和原文可支持的悬念。全文改编需明确采用该模式。输入本身未完结时，不能补写结局。

先建立重要事件与动机清单，再拆成逐页故事单元。每页写明：读者已知、本页新增信息、人物情绪变化、翻页留下的问题；不能只写“介绍人物”“推动剧情”。保留关键因果、关系和动机，不把小说逐段截图，也不压缩成只有旁白的梗概。

每格至少关联原文段落 ID／字符范围，并区分保留、改写和为画面衔接添加的过渡。用户要求保留的原话及推广关键词逐字一致。允许明确标记的闪回和叙事重排，但不能混淆事件时间或改变故事事实。改编过渡不得创造新的冲突、关系或结局。

取消全局固定页数和固定字数作为创作前提；文字量由手机可读性与情节表达决定。过密时优先拆对白、调分镜或增加页数，不能一路缩字。用户指定页数时，先在范围内调整镜头和信息密度，遇到明显不可兼得的关键取舍再请用户决定。

**3．建立可复用的美术标准和最小角色记忆**

把“Q版、精致、有情绪”等笼统形容，拆成可观察的线条、头身比例、眼睛与脸型、着色方式、背景细节、光影、气泡和字形规范。每项关联经本项目接受的样图，并记录版本。风格参考只提取视觉特征，第三方作品中的人物、画面和水印不直接变成本项目资产。

为主要角色建立身份卡，记录不可随意变化的特征与可按剧情变化的状态。服装、年龄阶段、受伤等持续变化用独立版本；场景和重要道具按需建参考，不要求每个配角生成五套设定图。风格预设可跨故事复用，人物身份资料按故事隔离。

参考图只有在真实传入接口时才记录为“使用了参考图”。仅在提示词写路径、只看过图片、或接口忽略参数，都不能算视觉约束成功。生产页始终优先引用固定的角色基准，避免每页接上一页导致漂移累积；经过审查的侧脸或表情可以补充图库，但不自动替换基准。

角色表演写成可见动作，例如回避目光、攥紧衣角、身体偏向另一人，而不只写“伤心”。三人关系需要时允许同框；模型处理不好则拆成建立关系的镜头、动作和反应，不把“最多两人”设成所有场景的铁律。

**4．用试样决定生产路线，保留完整漫画的效果目标**

| 路线 | 选择依据 | 制作与返工方式 |
|---|---|---|
| A：整页漫画 | 模型在试样中能稳定完成分格、中文、说话者与阅读顺序 | 输入完整导演说明和已验证参考；按页生成。文字或构图失败，使用已核验的编辑能力或重做该页 |
| B：整页无字画稿＋独立排字 | 模型能完成连续分格，但中文表现不稳定 | 先预留气泡空间，生成无字整页，再添加独立气泡与文字层；不以大块白底覆盖已生成的错误文字 |
| C：独立分格＋统一排字 | 模型难以稳定完成多格或多人 | 每格按最终画幅和构图生成，由统一模板组合；对白仍进入场景，不退化成图下固定字幕栏 |

模型能力和接口支持分开核验：支持参考图不等于保持角色，支持生成汉字不等于能写对长对白。少量试样中的表现作为路线依据；用户指定模型时，先在该模型内选择可行路线，不静默换成其他模型。

页面默认使用与已观察案例接近的3:4画布，其他比例服从用户和平台需求。整页、上下两格、主画面加反应小格等模板按叙事用途选择，不为“变化”刻意制造复杂分格。对白较多的页面优先保证清楚的左至右、上至下阅读路径。

分格生成前先确定目标画幅。模型不支持完全相同的比例时，选择最接近的规格并保留安全余量；裁切前检查脸、手、道具和构图重心。不能继续把所有4:3原画自动塞进约2.34:1画框。气泡尺寸随内容变化，尾巴指向正确角色，旁白、思考、普通对白和惊呼有适度区分。

气泡与文字层保留独立数据：说话者、形状、位置、尾巴目标、阅读顺序、不遮挡区域。先用已有原画验证排字与布局，减少排版调试时的无效生图。跨多页统一线宽、字体与边距，背景和文字的对比服从手机阅读。

**5．更换模型时，agent 自行查资料并生成调用配置**

这一项写入 Skill 的必要步骤，而不是让用户自行填写并发数或机械沿用60秒。首次使用新服务商、模型、地区端点、账号等级、分辨率、参考图通道或协议版本时重新核验；已缓存资料过期、接口返回参数错误、出现限流或权限变化时也触发复核。过期判断依服务商更新时间与运行迹象设置，不把永久缓存当成事实。

查证顺序为：实际服务商的模型与接口文档、账号可读取的当前限额／响应头、官方示例和更新说明；第三方 Skill 只提供线索。代理服务使用自己的限额，不能直接套上游厂商配额。文档与观测冲突时逐字段保留来源和不确定项，使用更保守的有效约束，不因为模型名字相似就视为同一协议。

agent 需记录以下结果，形成独立的 `provider-profile.json` 与简短 `provider-research.md`，均为拟新增产物：

| 配置范围 | 需确认的内容 |
|---|---|
| 身份与协议 | 服务商、模型精确 ID、端点／地区、同步或异步、认证方式、请求与返回格式 |
| 画面能力 | 尺寸／比例、参考图数量及用途、编辑／蒙版、文字能力证据；区分文档支持和已验证效果 |
| 限额 | RPM、RPS、IPM、每日额度、突发规则、在途任务上限；额度属于账号、项目、Key 类型还是模型共享池 |
| 调度 | 串行或有界并行、最大在途数、请求起始间隔、配额安全余量、异步轮询间隔和总截止时间 |
| 恢复与费用 | 错误分类、Retry-After、幂等与任务查询、重试预算、价格／免费权限是否已核实 |
| 证据 | 来源链接、查阅时间、版本／内容摘要、每个关键字段的可信状态与选择理由 |

串行和频控是两个不同约束：串行仍可能过快，并行也可以遵守RPM。调度器同时检查速率窗口、在途数、图片数／日额度和任务依赖。角色参考和首次风格样图先完成并审查；仅在它们之后的独立任务，才根据已核验限制并行。顺序依赖不因服务商允许并发就消失。

异步接口分别管理任务提交和结果查询：保存任务 ID，按官方说明查询，不把轮询当作重新生成；在途额度计算服务端未完成任务，而非仅计算当前HTTP连接。重启后先恢复既有任务，再决定提交新任务。

429先区分速率、日额度和费用限制，再按响应说明处理。503／队列满时退避、降低负载并限制尝试次数。401／403及余额、配额耗尽不盲目重试。提交超时不等于服务端未生成：能查询或使用幂等键时先恢复；不能确定状态时标为未知，不立即重复提交和释放在途额度。

所有重试、参考图、试样、失败候选都计入提交次数／费用预算，不能只统计成功图片。调度状态跨重启保留，同一限额池内的本机任务使用共享锁和配额记录。存在其他设备流量时，响应头和账号限额优先，不能声称本机锁能控制外部用量。不得轮换Key绕过共享限制。

资料不完整时不编造精确额度：记录未知项，使用并发1及有理由的低负载临时策略；在生成已获授权时，先完成一张低负载兼容性验证，不做压力测试，不凭少量成功请求推断峰值上限。用户限定免费而免费权限无法核实时，不自动开通付费或换收费模型。

本项目原 Agnes 2.5 案例的“串行、约60秒”仅作为同一已验证配置的历史运行记录。它不是其他模型的默认值；本轮查到的 Agnes 官方仓库目录较旧，未明确列出 image 2.5，不能把旧型号的RPM表直接当作2.5当前限制。宝玉适配中的并发3、起始间隔1.1秒同样不直接采用。

**6．建立能发现失败的验收与局部修复**

先审原画，再审排字后的整页，最后审全套顺序。每个问题都记录页／格ID、观察到的具体证据、严重程度、修复方式与复查结果；没有视觉工具或图片未能打开时，必须记“未审查”，不能用文件存在代替看图。

| 检查 | 拟采用的判断标准 |
|---|---|
| 剧情与因果 | 所选范围的关键事件、动机和信息揭示有对应表达；结尾悬念有原文依据；闪回清楚 |
| 人物与世界状态 | 当前格应出现的角色、服装与道具状态正确；有意换装、回忆色调或角色缺席不误判为漂移 |
| 构图与表演 | 情绪符合剧情，人物视线和动作有意义；无意外裁脸、关键道具缺失、明显错误肢体或人物关系不清 |
| 文字与阅读 | 关键原话和关键词一致；说话者和气泡尾巴正确；无溢出、错字、遮脸；约390像素宽预览清楚可读 |
| 页面完成度 | 气泡与场景结合，分镜服务剧情；不能以固定大字幕区填满页面；风格与已接受样图相符 |
| 技术交付 | 页数／排序／尺寸／文件／ZIP完整；无凭据或原文全文混入发布包 |

严重问题清零后交付。风格、情绪、节奏等主观项目可用带文字锚点的1–5分帮助比较，但评分不是客观流量指标，不能用平均分抵消错字、错误角色或错剧情。自动几何检测用于发现候选遮挡，最终的语义判断仍需要视觉审阅。

失败路由明确：文字和气泡问题只重排；单格画面问题只重绘该格；整页路线出现不可局部修复的问题才重做该页。改角色基准、上游脚本或布局后，根据依赖关系列出需要重审的下游产物。达到约定返工次数或预算后交付问题清单和当前可用结果，不无限抽图。

连续返工仍出现相同问题时，先检查生成要求和验收规则是否矛盾，避免错误审查导致反复重绘。新版与旧版对照时，使用同一故事事件的相应页面、相同显示宽度，去除版本优劣提示；若没有独立评审条件，只称“匿名展示比较”，不宣称双盲实验。参考案例用于风格目标，不作为不同剧情之间的严谨A/B实验。

**7．保持输入简单，内部产物足以复跑**

继续只要求标题／关键词与正文。沿用已确认风格、已核验模型配置时，agent 自动完成正常制作和内部审查，直接交付ZIP。允许自然语言要求只做脚本、只做试样、修改指定页或继续上次任务；不要求用户学习内部文件和参数。

本次迁移保留一次4张试样确认：新开篇、三人互动、正面对峙、悬念尾页。后续日常任务不强制重复多轮批准。新模型只是协议发生变化且保持已选风格时，由agent完成必要核验；重大画风取舍、费用变化或用户明确要求审样时再提供选择。

拟保留一个主 Skill，细节按需读取；“编剧／美术／审查”是流程职责，不要求额外付费服务、多agent或新聊天。脚本只负责稳定机械操作，创作判断与读图由agent完成。

拟新增或调整的资源包括：原文与逐页脚本规范、角色／场景状态、版式与气泡规则、模型发现与调度、视觉审查与修复，以及相应的模块化脚本和有意义的测试。当前单文件流程分离为规划校验、模型适配、调度、排字、验收和导出，保留现有配置兼容与旧产物读取能力。

产物内部保留输入摘要、稳定页格ID、脚本、美术版本、实际参考输入、模型配置快照、提示词、候选与最终图、问题记录、请求次数和预算消耗。缓存至少覆盖模型／服务端点、画幅、提示词、参考图哈希和风格版本；单纯换字体不应重生原画。编号是导出属性，插页时不改变既有页格身份。

交付同时提供：可直接上传的纯图片ZIP、总览和发布文案；需要复跑时另提供不含原文与凭据的制作资料包。正文及本机配置继续隔离。关键词与推广入口来自真实任务配置，测试占位词不能被当作已验证CPA任务；生成图集不自动发布社媒。

**8．实施顺序与验收依据**

| 阶段 | 工作 | 完成依据 |
|---|---|---|
| P0：配置与数据 | 新脚本结构、稳定页格ID、模型资料档案、预算与调度机制 | 模拟同步／异步、不同限额池、429／503／提交未知、重启与共享锁；不靠真实接口测限额 |
| P1：排版与美术 | 使用现有原画验证动态分格、气泡、阅读顺序和安全区域；建立角色与风格基准 | 手机尺寸能读；文字不遮关键内容；无固定大字幕带和无意裁脸 |
| P2：真实试样 | 用户确认实施后，按已核验模型完成4张代表页；必要时比较两种可行路线 | 提供与旧版的对应事件对照、具体问题单和真实请求统计；由用户确认方向 |
| P3：完整案例 | 用已选路线重做《测试小说》所提供范围，不编造缺失结局 | 全套逐页视觉与文本审查；严重问题清零；纯图片ZIP可用 |
| P4：Skill交付 | 完成安装包、配置说明、回归检查和仓库更新 | 新模型发现流程可复用，旧配置可迁移；代码检查与实际效果分别报告 |

P0测试只验证真实风险：速率窗口与并发同时成立、参考依赖先行、异步续作不重复提交、实际尝试预算、局部缓存失效、气泡溢出／遮挡、原文追溯和导出白名单。P2/P3检查实际漫画，不能被自动测试替代。第二个真实生图模型只在用户提供可用且获授权的配置后运行；否则以协议模拟验证可配置性，明确不宣称已完成第二模型实测。

验证收益限于能看到的改进：漫画阅读体验、角色和剧情准确性、返工范围与请求消耗。CPA转化需后续真实发布数据，不能由审图分数推导，也不纳入本轮效果承诺。

本方案确认后进入P0/P1，再制作4张试样。当前归档不等于批准实施或已经完成v3。
